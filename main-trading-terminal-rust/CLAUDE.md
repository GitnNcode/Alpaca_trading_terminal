# Chart + Compare + Terminal + Options + Crypto GUI (Rust + egui)

Five-tab desktop GUI:
- **Trading Terminal** — port of the canonical Go terminal's account-management surface; renders a *secondary* sub-tab strip beneath the top tab strip for `Positions / Trade / Orders / Activity`
- **Chart** — single-symbol multi-pane TradingView-style chart matching the main build's indicators. **Also charts crypto Pairs** (`BTC/USD`) — `get_bars` branches on slash symbols to `/v1beta3/crypto/us/bars`.
- **Compare** — multi-asset risk/return view (normalized lines, drawdown, scatter, Monte Carlo)
- **Options** — options desk with its own sub-tab strip `Chain / Positions / Orders`. Type an underlying, pick an expiration, see a calls/puts strike grid (bid/ask/last/vol/OI), place single-leg Market/Limit orders. See [src/options.rs](src/options.rs), [CONTEXT.md](CONTEXT.md), and [docs/adr/0001-options-chain-hybrid-rest-snapshot-plus-live-ws.md](docs/adr/0001-options-chain-hybrid-rest-snapshot-plus-live-ws.md).
- **Crypto** — crypto desk with sub-tab strip `Markets / Positions / Orders`. The Markets grid lists every tradable **USD-quoted** Pair (live bid/ask/last, 24h %, volume) and doubles as the trade entry point (B/S per row, like the Chain). Full ticket: Market / Limit / Stop-Limit, TIF GTC/IOC (crypto has no `day`), size as fractional Qty OR Notional dollars (notional is market-only). Reach it via `CRY [<PAIR>]`. See [src/crypto.rs](src/crypto.rs), [CONTEXT.md](CONTEXT.md), and [docs/adr/0002-always-warm-crypto-stream-full-chart-integration.md](docs/adr/0002-always-warm-crypto-stream-full-chart-integration.md).

## Stack
- Rust 2021, `eframe` 0.29 + `egui` 0.29 + `egui_plot` 0.29
- `ureq` for HTTP, `tungstenite` 0.24 (native-tls) for the live data WebSocket, `chrono`, `serde` / `serde_json`, `csv`, `dirs`, `anyhow`
- 18 source files in [src/](src/), 104 tests

## Commands (run from this directory)
- Build: `cargo build --release` (output: `target/release/alpaca-egui`)
- Run: `cargo run --release`
- Reset stored credentials: `cargo run --release -- --reset`
- Test: `cargo test` (106 tests — indicators + compare math + terminal order-build + command parser + options OCC/chain/order-build + crypto pair/order-build/symbol-canonicalization + date-intersection alignment + chart axis/visible-window helpers)
- Live-probe tests (`--ignored`, hit real Alpaca, close the app first): `live_mutual_exclusion_handoff` (ADR-0001), `live_crypto_and_stock_concurrent` (ADR-0002)
- **Windows cross-build (from macOS):** `CARGO_TARGET_DIR=/tmp/alpaca_win_target cargo build --release --target x86_64-pc-windows-gnu`. The space-free target dir is REQUIRED — MinGW `dlltool`/`windres` choke on the repo's "Codeing stuff" path. [build.rs](build.rs) embeds the `.exe` icon from [assets/icon.ico](assets/icon.ico) (regenerate from the logo with [assets/make-ico.sh](assets/make-ico.sh)) by driving `x86_64-w64-mingw32-windres` directly — it no-ops for every non-Windows target (macOS universal, CI Linux), so it never touches those builds. winit also auto-adopts the embedded icon as the runtime window/taskbar icon on Windows.

## Architecture rules

- **Tab routing.** `Tab` enum in [src/app.rs](src/app.rs) selects Chart / Compare / Terminal / **Options** / **Crypto**. **Chart-tab indicator hotkeys (`V B S E U I O`) are gated on `current_tab == Tab::Chart`** so they don't fire silently on other tabs. Terminal, Options, and Crypto each render their own sub-tab strip right under the top strip with number hotkeys gated on focus (Terminal `1..4` for Positions/Trade/Orders/Activity; Options `1..3` for Chain/Positions/Orders; Crypto `1..3` for Markets/Positions/Orders). There are NO top-tab number hotkeys — top tabs switch by click or command-palette code.
- **Options desk** ([src/options.rs](src/options.rs), [docs/adr/0001](docs/adr/0001-options-chain-hybrid-rest-snapshot-plus-live-ws.md)). Hybrid Chain data: `client.get_option_contracts` (skeleton + OI + prev-close — **must pass an `expiration_date_gte/lte` window or the endpoint returns only the few nearest expirations**) + `client.get_option_snapshots` (indicative feed: bid/ask/last; **no greeks/IV** — OPRA unsigned, so v1 shows none) + a SECOND WebSocket overlaying live bid/ask. Single-leg Market/Limit orders only, built by `options::build_option_order` and routed through the same two-phase confirm modal as Terminal (OCC symbol flows through `/v2/orders`). Lazy-primed (`options_primed`) + 10s refresh of options Positions/Orders, exactly like Terminal. Reach it via the `OPT <TICKER>` palette code. Positions/Orders are filtered to `asset_class == "us_option"`; the Terminal tab is left unfiltered (options may appear in both — intentional).
- **Three live data streams, one tick cache.** `stream::spawn_stream` is called three times in `ChartApp::new` — stocks (`STREAM_URL`, IEX, `report_status=true`, `subscribe_bars=true`), options (`OPTIONS_STREAM_URL`, `/v1beta1/indicative`, `report_status=false`, `subscribe_bars=false`), and crypto (`CRYPTO_STREAM_URL`, `/v1beta3/crypto/us`, `report_status=false`, `subscribe_bars=true`, **always active**). All write symbol-/OCC-/Pair-keyed entries into the SAME shared `TickCache` (no key collision). The options stream subscribes to the displayed expiration's contracts ∪ held option positions, ONLY while the Options tab is open; **stock and options do a `SetActive` handoff because they share Alpaca's single-connection limit**. The crypto stream sits OUTSIDE that handoff — its endpoint has its own connection allowance (verified live; see ADR-0002 and the `live_crypto_and_stock_concurrent` test) — and its subscription set is the union (chart Pair ∪ Compare Pair slots ∪ watchlist Pairs ∪ held crypto positions ∪ Markets-grid Pairs while on the Crypto tab). **The stock stream's union must EXCLUDE slash symbols** — `sync_stream_subscriptions` splits Pairs out to the crypto stream. **Don't make the options or crypto stream report status** — the stock stream owns the single `stream_connected` flag.
- **Crypto desk** ([src/crypto.rs](src/crypto.rs), [docs/adr/0002](docs/adr/0002-always-warm-crypto-stream-full-chart-integration.md)). The Markets grid plays the Chain's role: `/v2/assets?asset_class=crypto` (filtered to tradable `*/USD` by `usd_pairs`) + a bulk `/v1beta3/crypto/us/snapshots` seed + live WS overlay; B/S buttons per row route through `build_crypto_order` → the same two-phase confirm modal. Ticket: Market/Limit/Stop-Limit × Qty/Notional × GTC/IOC, validated per-combination (`build_crypto_order` returns a user-facing error string — notional is market-only, stop-limit needs both prices, crypto has NO `day` TIF and NO plain stop). **Symbol identity:** the slash form is canonical everywhere in the app; the trading API returns crypto slashless (`BTCUSD`) so `canonical_crypto_symbol` normalizes positions/orders at the API boundary (`fills_for_symbol` additionally matches slashless activity symbols). Bare-coin → `/USD` inference happens ONLY in crypto-scoped inputs (`CRY` code via `command::normalize_pair`, the desk's pair filter) — `BTC` alone is a real equity ticker. Lazy-primed (`crypto_primed`) + 10s refresh of crypto Positions/Orders, exactly like Terminal/Options; both are filtered to `asset_class == "crypto"`, Terminal stays unfiltered (intentional overlap). Reach it via `CRY [<PAIR>]`. **The `AssetCache` autocomplete universe includes USD Pairs** — `spawn_assets` merges `get_crypto_assets` (filtered through `crypto::usd_pairs`) into the equity list, so the Chart toolbar / Compare picker / palette / watchlist all suggest `BTC/USD` for "BTC" (and for "bitcoin", via name search).
- **Background HTTP.** `std::thread` + `mpsc::channel` in [src/workers.rs](src/workers.rs). `Msg` variants: `Assets`, `Bars` (Chart), `CompareBars` (Compare per-slot), plus the Terminal-tab set: `Positions`, `AccountInfo`, `OpenOrders`, `ClosedOrders`, `Activities`, `OrderPlaced { req_summary, result }`, `OrderCancelled { id, result }`, plus the `Opt*` and `Crypto*` desk sets. Every worker calls `ctx.request_repaint()` after sending.
- **Terminal tab is lazy + auto-refresh.** Nothing is fetched until the user first opens the Terminal tab (`terminal_primed: bool` flips on first visit). While the tab is active, `ChartApp::update` checks `terminal.last_refresh.elapsed() >= 10s` every frame and re-runs `TerminalState::refresh_all` — matches the Go terminal's 10s background goroutine. A `ctx.request_repaint_after(1s)` keeps the timer honest when the user isn't moving the mouse. Don't run the refresh while on Chart/Compare — burning API calls on a tab nobody is looking at.
- **Order placement is two-phase.** Clicking PLACE ORDER in the Trade sub-tab does *not* hit Alpaca directly; it stashes the validated `OrderRequest` in `terminal.place_confirm` and pops an `egui::Window` modal. Only the modal's CONFIRM button calls `workers::spawn_place_order`. Same shape for cancels via `cancel_confirm`. **Don't bypass this** — the Go terminal's tests lock in the confirm-before-fire UX.
- **Cancelling-state lifecycle.** When a CANCEL row button is clicked, the order id is added to `terminal.cancelling: HashSet<String>` for an inline "cancelling…" label. The set is pruned in two places: when `Msg::OrderCancelled` arrives (immediate remove) AND when `Msg::OpenOrders` returns and the id is no longer in the live list (defensive — covers the rare case where the cancel message is lost but the order really did clear).
- **Stale-response protection differs by tab.**
  - Chart tab: single `gen: u64` on `ChartApp` (one symbol at a time, same pattern as the main build's `chartLoadGen`).
  - Compare tab: **per-slot gens.** Each `Slot` carries its own `gen`; `CompareState::seq` is a monotonic counter that issues a fresh gen for every load. Load-bearing — adding a second asset while the first is still loading must NOT invalidate the first's pending response, so a single global gen wouldn't work.
- **Compare lock toggle.** `egui_plot` captures mouse-wheel/drag inside the plot area by default, which fights the outer `ScrollArea`. `CompareState::interactive` (default `false`) gates this:
  - Locked: every Compare plot gets `allow_drag/scroll/zoom = Vec2b::FALSE` and `ScrollArea::enable_scrolling(true)`, so the page scrolls past charts.
  - Unlocked: the inverse.
  - The `apply_lock(plot, interactive)` helper in [src/compare.rs](src/compare.rs) is the single place to flip this — **every new chart in Compare must route through it.**
- **Series alignment is by DATE, not index.** Symbols differ in bar history (IPO date) AND calendar (crypto trades 7-day weeks, equities 5). `aligned_closes()` intersects on bar date, so every series shares one length and one calendar — a mixed BTC/USD + AAPL compare collapses to equity trading days. Don't add length-mismatched arithmetic and don't revert to right-truncation by length — it silently compares different calendar windows for mixed sets.
- **Annualization cadence is per-comparison.** `periods_per_year(symbols)` returns 365.25 only when EVERY slot is a crypto Pair, else 252 (matching what the date intersection leaves). All metric fns (`cagr` / `annualized_vol` / `sharpe` / `sortino` / `calmar` / `run_monte_carlo`) take `ppy` explicitly — don't re-hardcode 252 inside them. Pure-equity results are unchanged from the pre-crypto build.
- **Monte Carlo RNG is inline** (`Xorshift64` + Box-Muller in [src/compare.rs](src/compare.rs)) on purpose — adding the `rand` crate for one tab was rejected. The seed advances by an LCG step on each Re-run so successive runs give different draws but a single run is reproducible. Sim count is a typeable `DragValue` clamped to 100–10000; higher × 10y horizon ≈ 200MB working set.
- **Theme palette.** [src/theme.rs](src/theme.rs) is shared across both tabs. Compare uses `SLOT_COLORS` (cyan/orange/yellow/green) keyed by slot index — same color reused for the chip, stats-row dot, normalized line, drawdown line, and scatter point so the eye can track each asset.
- **State persistence is end-of-frame, debounced, best-effort.** [src/persist.rs](src/persist.rs) defines `AppState` (last symbol / range_idx / tf_idx / indicator toggles / compare slots / compare range / watchlist). `ChartApp::snapshot_state` builds one from the live fields each frame; `maybe_save_state` compares to `last_saved_state` and arms a 1-second debounce when they diverge, then flushes to `{config_dir}/alpaca-tui/state.json`. **Don't add hand-rolled "mark dirty" calls scattered through the code** — the structural diff handles every persistable field uniformly. New persistable state means: add the field to `AppState`, populate it in `snapshot_state`, restore it in `ChartApp::new` (and clamp any persisted indices via `.min(LEN - 1)` so a file from a future build can't index out-of-bounds in an older binary). The debounce path also calls `ctx.request_repaint_after(remaining)` so the save fires when the user has gone idle. State load is fault-tolerant — any error returns `AppState::default()`.
- **Live data streams through a separate thread + shared cache, not the Msg channel.** [src/stream.rs](src/stream.rs) holds a long-lived WebSocket (`wss://stream.data.alpaca.markets/v2/iex`), auths, manages the active subscription set, parses trade / quote / minute-bar frames into `Arc<RwLock<HashMap<String, LastTick>>>` (the `TickCache`), and calls `ctx.request_repaint()` on every tick. Only connection / latency state flows through `Msg::StreamStatus` — moving 1000 ticks/sec through the mpsc would dominate the UI loop. **Don't push individual ticks via `Msg`** — the cache is the contract. Subscription set is the union of (chart symbol ∪ compare slots ∪ positions ∪ watchlist), recomputed end-of-frame and pushed to the stream thread via a `SubMsg::SetSubscriptions` channel only when it differs from the last sent set. The stream thread further diffs against what's actually subscribed before emitting subscribe/unsubscribe frames.
- **Chart consumes live ticks via `patch_bars_with_live`.** [src/chart.rs](src/chart.rs) reads `app.tick_cache` once at render-start, and `patch_bars_with_live` returns `Some(Vec<Bar>)` only when there's actually something to overlay (otherwise the no-stream path stays zero-allocation). Three patch cases: streamed minute bar same-minute → replace last bar; streamed minute bar later-minute → append; raw trade tick with timestamp > last bar's open → update close + extend high/low. **All EMA / SMA / Bollinger / VWAP / RSI / MACD indicator math is computed against the patched bars** — so every indicator moves tick-by-tick as a side effect, no per-indicator wiring needed.
- **Chart panes auto-scale Y to the visible X window** (TradingView behavior) whenever the Y axis is locked (`zoom_y == false`, the default) — price/volume/MACD panes call `set_plot_bounds` inside their show closures. The price pane fits from its own bounds, gated on `!plot_ui.auto_bounds().x && !reset_view` (in auto-bounds mode / on the HOME frame the remembered bounds are garbage or about to be recomputed). **The volume/MACD panes must take their X window from `price_x_window` (the price pane's `PlotMemory`), never from their own `plot_ui.plot_bounds()`** — `BoundsModification::Set` replaces BOTH axes after the link-group transfer, so fitting from a sub-pane's own (last-frame) bounds clobbers the linked X, writes the stale X back to the group, and the panes fight the user's pan instead of moving in tandem. Two more chart invariants: candle wicks are drawn by the `BoxElem` *stroke* (so `Stroke::NONE` silently deletes all wicks — keep the 1px same-color stroke), and the time axis (`make_time_axis_formatter`, index → date) renders on the bottom-most visible pane only.
- **Positions table recomputes from live ticks too.** [src/terminal.rs](src/terminal.rs) `positions_view` takes the tick cache, reads it once for the whole table (single read-lock; cheap), and recomputes Current / Mkt Value / P&L / P&L% on every frame between the 10-second `/v2/positions` refreshes. Shorts get `side_sign = -1.0`. The CURRENT cell is colored ORANGE when the value came from the stream vs WHITE when from the broker snapshot — visual cue that the value is live.
- **Command palette is one TopBottomPanel above the tab strip.** [src/command.rs](src/command.rs) is a pure parser (no app deps, fully unit-tested); [src/app.rs](src/app.rs) `dispatch_command` applies the resulting `Command` to ChartApp / Compare / Terminal / Watchlist. `/` hotkey focuses the palette via `ctx.memory_mut(|m| m.request_focus(palette_id))`. **Don't add app-mutating logic to the parser** — keep it pure so the test suite stays exhaustive. New function codes go in `command::parse` + a new arm in `dispatch_command`.
- **Watchlist + ticker tape ride on the existing tick cache.** [src/watchlist.rs](src/watchlist.rs) is mounted across every tab (left `SidePanel` + bottom `TopBottomPanel::bottom`). Reading the cache by symbol; no separate data plumbing. Clicking a watchlist row commits the symbol to the Chart tab (`load_from_sidebar` outcome → `kick_off_load`). Ticker tape animates via `(ctx.input.time * speed) % row_width` and calls `ctx.request_repaint()` to keep moving. Symbol list persists via the existing `AppState.watchlist` field.
- **Advanced order types layer onto OrderRequest without breaking simple orders.** [src/api.rs](src/api.rs) added `stop_price` / `trail_percent` / `order_class` / `take_profit` / `stop_loss`, all `Option` with `#[serde(skip_serializing_if = "Option::is_none")]`. **The simple Market/Limit serialization is byte-identical** to before — Alpaca rejects unknown fields on the wrong order_type, so omission is load-bearing. `build_order` in terminal.rs validates per-kind (only emits stop_price for Stop / StopLimit, only emits trail_percent for TrailingStop) and per-bracket (rejects partial brackets). The `OrderKind` enum's `needs_limit / needs_stop / needs_trail` helpers gate the form rows; **don't grey-out unused fields** — render only the rows the kind actually uses, keeps the form short.
- **Trade-history markers re-use the strategy-marker primitive.** [src/chart.rs](src/chart.rs) calls `app.terminal.fills_for_symbol` (in `TerminalState`) which merges activities + closed_orders (de-duped by `order_id`, falls back to closed_orders only when activity feed didn't emit a fill row for the order). Markers are `MarkerShape::Diamond` (cyan buys / orange sells) so they're visually distinct from the strategy markers (triangle Up/Down, green/red). **The fill data is only populated after the user visits the Trading Terminal tab at least once** — that's where the activity refresh fires. Default-Terminal-as-first-tab works in our favor here.

## Don't

- Don't add a chart to the Compare tab that bypasses `apply_lock` — it'll fight the outer `ScrollArea`.
- Don't pull in the `rand` crate just for Monte Carlo; extend `Xorshift64` instead.
- Don't do arithmetic on close-arrays of different lengths without going through `aligned_closes()`.
- Don't ungate the indicator hotkeys from the Chart tab — they'll silently fire on Compare / Terminal.
- Don't make Terminal-tab fetches at app startup. Fetching has to be gated on `current_tab == Tab::Terminal` so first-launch latency stays on Chart.
- Don't call `place_order` / `cancel_order` from a button click — route through the confirm modal (`place_confirm` / `cancel_confirm`).
- Don't restore the Go terminal's Chart sub-tab here. The egui app already has a richer Chart top-level tab; duplicating it inside Terminal would just confuse the tab strip.
- Don't push individual ticks through the `Msg` channel — they go directly into the `Arc<RwLock<TickCache>>`. The `Msg` channel is for control state only.
- Don't add side effects to `command::parse` — keep it pure. All mutation lives in `ChartApp::dispatch_command`.
- Don't grey-out unused order fields. Render only the rows the current `OrderKind` actually needs (`needs_limit` / `needs_stop` / `needs_trail`).
- Don't send a bracket order without both legs — `build_order` validates and rejects partial brackets. Alpaca returns 422 on missing TP or SL.
- Don't hardcode the stream URL outside [src/stream.rs](src/stream.rs). One place to swap to `/sip` or `/test` when feed tier changes.
- Don't put slash symbols (Pairs) into the stock stream's subscription set — the IEX feed rejects them; `sync_stream_subscriptions` splits them out to the crypto stream.
- Don't add the crypto stream to the stock↔options `SetActive` handoff — its endpoint has its own connection allowance (ADR-0002). If it ever logs 406 "connection limit exceeded", that assumption broke; fold it into the handoff then, not before.
- Don't infer `/USD` from a bare coin symbol outside crypto-scoped inputs — `BTC` is a real NYSE ticker (Grayscale Bitcoin Mini Trust).
- Don't send `tif=day`, a plain `stop`, or a non-market notional order for crypto — Alpaca rejects all three; `build_crypto_order` validates them away.
- Don't assume integral sizes/volumes in stream frames or bars — crypto is fractional; the wire types are f64 (truncated to i64 only for `Bar.volume`).
